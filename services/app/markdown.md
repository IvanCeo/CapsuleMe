7) работа с путями к CSV

Относительные пути хрупкие. Варианты:
go:embed CSV в бинарь (максимальная переносимость);
читать путь из ENV (CSV_PATH), с дефолтом;
убедиться, что workdir в контейнере фиксирован.
Важно: для Go-миграций файл должен быть доступен в рантайме того бинаря, который выполняет миграции.

8) порядок запуска (суммарно)

Собрать бинарь, который содержит:
код приложения,
пакет postgres,
директорию миграций с .sql и .go файлами (включены в сборку).
Приложение/CLI/иниц-контейнер:
NewPostgres(ctx) → пул,
RunMigrations(ctx, "<путь к миграциям>") → goose.Up(...),
(опционально) отдельный seed-шаг, если не включили загрузку CSV в миграцию,
запуск сервиса.

отличия доменов от usecase

ДОМЕН:

Содержит:

Entities (SurveySession, ImageItem)
Value Objects (IncomingFeature)
Domain Services (SurveyEngine, Recommender)
Доменные ошибки и инварианты

Характеристики:

ничего не знает о БД, HTTP, логировании;
не использует context.Context;
не вызывает инфраструктуру;
не зависит от внешнего мира;
можно запускать в чистых юнит-тестах без моков.

USECASE

Содержит:

сервисы (SurveyService, CatalogService);
координацию доменных операций;
обращение к репозиториям, мапперам, адаптерам;
трансформацию данных между слоями.

Характеристики:

может вызывать инфраструктуру через интерфейсы;
управляет транзакциями, контекстом, логами;
знает порядок действий (workflow), но не детали домена.
